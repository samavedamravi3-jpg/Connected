# Guardrails and misuse controls

Layers: shared rules (`supabase/functions/_shared/moderationRules.ts`) in the app -> the same rules in DB triggers (generated by `scripts/gen-moderation-sql.ts`) -> for profile org / intro / offer, a contextual AI review in the `profile-write` edge function (via the assistant server's `/moderate`). Full inventory and design: docs/moderation.md.

## What happens when something is unavailable
| Situation | Result |
|---|---|
| Profile review not configured (`MODERATION_URL`/`MODERATION_TOKEN` unset), provider error, timeout or malformed answer | Profile text stays unpublished: kept as a private draft (`profile_drafts`), the rest of the profile saves, the app says "kept as a private draft… try again". |
| `profile-write` not deployed (after the migration) | Profile saves fail ("Couldn’t save your profile"); nothing is published. |
| `EXPO_PUBLIC_ASSISTANT_URL` unset | Best-effort AI check for chat / notes / experience skipped; rules in the app and DB still apply. |
| Server up, no provider key, or provider error | `/moderate` returns 503: borderline chat text is refused with "Try again in a moment"; profile text becomes a draft. |

## Misuse controls
- Reports: one per reporter per subject; 3 distinct reporters auto-hide a profile (events via `hidden_event_ids()`). Restore: `update public.profiles set hidden = false where id = '<uuid>';`
- Hidden accounts cannot send connection requests (`account_restricted`). Profile rows cannot be deleted by users.
- Rate limits (`rate_check`): requests 10/day strict (new <24h or unverified), 15 trusted; profile text edits 120/hour; reports 10/30 per day. Strict values were raised for the demo (production: 3 requests/day, 30 edits/hour).
- Mutes hide someone from alerts server-side; map/search use local state.
- Review queue: `select * from public.admin_review_queue;` (SQL editor / service role only). Audit trail: `public.audit_log`.

## ID verification gate
`app_config.id_gate` is `off`. Turn on only after Stripe works: `update public.app_config set value='on' where key='id_gate';`

## Known limits
- Three throwaway accounts can still auto-hide a profile (reports are not weighted by verification).
- Open Door limits are client-side (doors live on the phone).
- Rules miss harmful text with no listed phrase; only profile org / intro / offer get the AI review.
