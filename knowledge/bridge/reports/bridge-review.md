## What holds up
- **Ownership:** `claim`, `complete` and `block` require `--agent` to equal the task owner (covered by the test).
- **Overlapping active claims:** two edit tasks cannot both be `active` or `review` on the same normalized path (test plus sandbox).
- **Independent acceptance:** an owner cannot accept their own task under their own name. `accept` also rejects when scoped files changed after `complete`.
- **Stale review:** a review whose files change between `claim` and `complete` becomes `needs-refresh` and cannot be accepted.
- **Path handling:** absolute paths, `..`, and symlinks that leave the project are rejected. `./.env` and `./.git/x` are normalized first and then re-checked, so they are rejected too. A directory as scope is rejected.
- **State writes:** atomic temp-file + rename for `tasks.json`; `mkdir` lock with `finally` cleanup; the lock is under the ignored `/work/`.
- **Tests:** `npm test` → 11/11 pass (including `bridge enforces ownership, independent acceptance, and stale-review protection`).

## Concrete defects (most severe first; each reproduced in the sandbox)
1. **Blocking or requeuing an edit task releases its files.**
   - The conflict check (`scripts/bridge.mjs:173-183`) only considers tasks in `active`/`review`.
   - Repro C: `claim blk-one` → `block blk-one` → `claim blk-two` on the same file **succeeds**. The original owner's re-claim then fails with "Overlapping edit scope is owned by blk-two".
   - Repro D: `complete` → `requeue` frees the files the same way, while the unaccepted edits are still on disk.
   - This contradicts Protocol's "Two active edit tasks cannot own the same file" in spirit, and its Recovery promise that another agent cannot silently take a stalled task's files.
   - Suggested fix: treat any edit task that has a `startedAt` and is not `accepted` as holding its files.
2. **Overlap check is case-sensitive on a case-insensitive disk.**
   - This Mac's volume is case-insensitive APFS (`diskutil`: "APFS").
   - Repro B: `lib/server.ts` and `lib/Server.ts` are the same file, yet both edit tasks were claimed `active` at once.
   - Suggested fix: compare `fs.realpathSync.native` for existing files, or lowercase keys on case-insensitive volumes.
3. **Agent identity is self-asserted, so "an agent cannot accept its own result" is honor-system only.**
   - Repro E: a task owned by `claude` was accepted by the same process passing `--agent codex`.
   - The same applies to `send`'s sender, `requeue`, and `--agent human`.
   - Can't be fixed without separate credentials. Suggested fix: Protocol should say acceptance relies on each agent using its own name, and that `acceptedBy` is recorded and auditable, not enforced.
4. **Handoffs have no inbox and `status` doesn't show them.**
   - `status` prints tasks only, and `Board.md` lists just the last 12 messages.
   - There is no command to list or acknowledge messages for an agent, so "Codex consumes it during the active work loop" means opening `Board.md` or `tasks.json` by hand.
   - Also, `Board.md` says "Generated by `npm run bridge -- status`", but `status` never writes it (repro G: the board stayed missing after `status`). Only state-changing commands regenerate it.
5. **Handoff text is rendered into `Board.md` unescaped** (`scripts/bridge.mjs:81`).
   - Repro F: a message containing newlines injected a `## Fake heading` and table row into the board.
   - Low risk between two cooperating agents, but it breaks the generated note. Suggested fix: collapse whitespace or indent continuation lines.
6. **Secret-path filter is top-level only** (`scripts/bridge.mjs:28-30`).
   - `sub/.env` was accepted as a scope (repro A). The local D1 files under `.wrangler/state/**.sqlite` are also accepted.
   - Impact is small: the bridge only hashes scoped files and never prints them. But a stored hash of secret contents is still not ideal.
   - Suggested fix: match `.env*`/`.dev.vars*` on any path segment and reject `.wrangler/`.

Minor, not defects: `complete` accepts any existing report under `knowledge/bridge/reports/` (including another task's); `mutate` reports any `mkdir` failure, such as a permissions error, as "Another bridge update is running"; `Board.md` is rewritten non-atomically after the atomic JSON rename.
